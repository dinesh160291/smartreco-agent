# Platform Glossary

**Version:** 1.0

---

# Purpose

The Platform Glossary defines the canonical vocabulary used throughout the Behavioral Intelligence Platform.

Every architectural document in this repository uses the terminology defined here.

The glossary exists to ensure:

- Consistent communication
- Shared understanding
- Clear ownership
- Precise architectural language

The glossary defines terminology.

It never defines implementation.

---

# Guiding Principle

Every important architectural concept has exactly one canonical definition.

If a term is defined here, every document in the repository should use that definition consistently.

---

# Canonical Vocabulary

The Platform Glossary is the authoritative source for platform terminology.

When terminology evolves:

1. Update the glossary.
2. Update dependent architecture documents.
3. Deprecate obsolete terminology.

New terminology should never appear in architecture documentation before being added to this glossary.

# Core Platform Concepts

## Behavioral Intelligence Platform

The deterministic platform responsible for transforming observed behavior into trusted business intelligence.

The platform establishes truth.

AI communicates truth.

---

## Platform Engine

A deterministic software component responsible for performing exactly one platform responsibility.

Platform Engines:

- Determine truth.
- Consume Runtime Objects.
- Produce Runtime Objects.

Platform Engines never:

- Invoke AI.
- Hardcode business policy.
- Modify upstream Runtime Objects.

---

## Runtime Object

An immutable, versioned representation of deterministic platform knowledge.

Runtime Objects are the exclusive communication mechanism between platform components.

---

## Decision Policy Framework (DPF)

The governance layer responsible for authorizing deterministic business actions.

Decision Policies determine:

- What is allowed.
- When actions are permitted.

Platform Engines determine truth.

Decision Policies authorize actions.

---

## AI Buying Advisor

The AI communication layer responsible for transforming deterministic platform outputs into user-facing communication.

The AI Buying Advisor never establishes truth.

It communicates deterministic platform outputs.

---

## AI Advisory Response (AAR)

The structured user-facing artifact generated by the AI Buying Advisor.

The AI Advisory Response communicates deterministic platform knowledge.

It never changes deterministic platform decisions.

---

## Runtime Object Model (ROM)

The canonical specification defining the structure, ownership, lifecycle, relationships, and governance of every Runtime Object used by the platform.

---

# Behavioral Concepts

## Behavioral Event

An immutable representation of an observed user action.

Behavioral Events contain facts only.

They never contain behavioral interpretation.

---

## Behavioral Evidence

Normalized deterministic evidence extracted from one or more Behavioral Events.

Behavioral Evidence supports Behavioral Hypothesis generation.

---

## Behavioral Hypothesis

A probabilistic deterministic belief inferred from Behavioral Evidence representing possible user intent or requirements.

Behavioral Hypotheses evolve as additional evidence becomes available.

---

## Behavioral Memory

The accumulated deterministic behavioral understanding associated with a Journey.

Behavioral Memory preserves long-term behavioral understanding.

---

## Behavioral Profile

A long-term behavioral representation derived from completed Journeys.

Behavioral Profiles support learning across multiple Journeys.

---

## Confidence

The deterministic measure representing how strongly the platform believes a Behavioral Hypothesis or Requirement is supported by available Behavioral Evidence.

Confidence is produced exclusively by the Confidence Engine.

It is never generated by AI.

---

## Requirement

A deterministic representation of an inferred user need derived from Behavioral Hypotheses.

Requirements are independent of products.

They describe what the user needs, not what they should buy.

---

## Requirement Profile

The canonical Runtime Object containing the complete set of inferred Requirements for a Journey.

Requirement Profiles are produced by the Requirement Engine.

---

# Journey Concepts

## Journey

A deterministic representation of a user's progression toward achieving a specific business objective.

A Journey groups related Sessions that contribute toward the same objective.

A Journey is independent of chat conversations.

---

## Session

A bounded period of user interaction occurring within a Journey.

A Session contains one or more Behavioral Events.

Every Session belongs to exactly one Journey.

---

## Journey Resolution

The deterministic process of assigning an incoming Session to an existing Journey or creating a new Journey.

Journey Resolution is performed exclusively by the Journey Resolution Engine.

---

## Journey Resolution Result (JRR)

The Runtime Object produced by the Journey Resolution Engine representing the deterministic outcome of Journey Resolution.

---

## Journey Lifecycle

The operational state of a Journey.

Journey Lifecycle answers:

> "What is the operational status of this Journey?"

Examples include:

- NEW
- ACTIVE
- DORMANT
- CLOSED
- ARCHIVED

Journey Lifecycle is independent of Journey Stage.

---

## Journey Stage

The user's current position within a business Journey.

Journey Stage answers:

> "Where is the user in the business process?"

Journey Stages are defined by the active Domain Pack.

---

## Journey Outcome

The final deterministic business outcome of a completed Journey.

Examples include:

- PURCHASED
- ABANDONED
- CANCELLED
- NO_DECISION

Journey Outcomes contribute to long-term behavioral learning.

---

# Recommendation Concepts

## Recommendation

A deterministic product recommendation produced by the Recommendation Engine.

Recommendations are never generated directly by AI.

---

## Recommendation Engine

The deterministic platform engine responsible for matching Requirement Profiles against Product Capability Profiles.

The Recommendation Engine determines recommendation truth.

---

## Recommendation Package

The immutable Runtime Object containing the deterministic recommendation outcome for a Journey.

The Recommendation Package is consumed by the AI Buying Advisor.

---

## Recommendation Readiness

A deterministic platform state indicating whether sufficient evidence exists to publish recommendations.

Recommendation Readiness is determined by the Recommendation Engine together with the Decision Policy Framework.

---

## Recommendation Constraints

Deterministic explanations describing why Recommendation Readiness has not yet been achieved.

Recommendation Constraints are communicated to the user by the AI Buying Advisor.

---

## Capability Matching

The deterministic process of comparing inferred Requirements against Product Capability Profiles.

Capability Matching never invokes AI.

---

# Product Concepts

## Product Catalog

The canonical repository of deterministic product knowledge consumed by the Recommendation Engine.

---

## Product Capability Profile (PCP)

The structured representation of a product's supported business capabilities.

Product Capability Profiles are consumed by the Recommendation Engine.

---

## Business Capability

A vendor-neutral description of a business function supported by one or more products.

Examples include:

- Workflow Automation
- API Integration
- Reporting
- Security
- AI Assistance

Business Capabilities are owned by Domain Packs.

---

# AI Concepts

## Large Language Model (LLM)

The AI technology responsible for generating natural language communication.

Within this platform, LLMs communicate deterministic platform outputs.

They never establish platform truth.

---

## LLM Contract

The canonical contract governing how Large Language Models interact with the Behavioral Intelligence Platform.

The LLM Contract defines:

- Approved Runtime Objects
- Prompt Structure
- Output Schema
- AI Boundaries

---

## Grounding

The requirement that every AI-generated statement be supported by approved deterministic Runtime Objects.

Grounding prevents unsupported AI-generated information.

---

## Hallucination

Any AI-generated statement that is not supported by approved Runtime Objects.

Hallucinations are prohibited.

---

## Prompt

A structured instruction provided to a Large Language Model.

Prompts are versioned.

Prompt evolution never changes deterministic platform reasoning.

---

## Prompt Library

The collection of reusable Prompt templates maintained by the platform.

Prompt templates are versioned and governed through the LLM Contract.

---

# Platform Infrastructure Concepts

## Event Schema

The canonical contract defining the structure of Behavioral Events entering the platform.

The Event Schema validates structure.

It never infers meaning.

---

## Platform Enumerations

The canonical vocabulary defining strongly typed categorical values shared across the platform.

Platform Enumerations are owned by the Core Platform.

---

## Domain Pack

A pluggable extension that provides domain-specific knowledge while preserving a domain-agnostic Core Platform.

Domain Packs define:

- Event Types
- Journey Stages
- Product Categories
- Business Capabilities
- Product Definitions

---

## API Contract

The canonical interface through which external systems interact with the Behavioral Intelligence Platform.

API Contracts expose platform capabilities.

They never expose implementation details.

---

# Governance Concepts

## Deterministic Reasoning

The process of producing identical outputs when given identical inputs.

Deterministic reasoning establishes platform truth.

---

## Observability

The platform capability that records deterministic platform execution for debugging, replay, auditing, and monitoring.

Observability spans the entire platform.

---

## Replay

The deterministic reconstruction of historical platform behavior using historical Runtime Object Versions, Decision Policy Versions, Enumeration Versions, and Product Catalog Versions.

Replay reproduces deterministic reasoning.

It never modifies history.

---

## Explainability

The ability to trace every deterministic platform decision back to its supporting Runtime Objects and Decision Policies.

Every deterministic platform decision is explainable.

---

## Traceability

The ability to follow Runtime Objects throughout their complete lifecycle.

Traceability supports replay, observability, and auditing.

---

## Versioning

The platform capability that preserves historical behavior by maintaining immutable versions of Runtime Objects, contracts, policies, enumerations, prompts, and product knowledge.

# Reserved Terms

The following terms have precise meanings within the Behavioral Intelligence Platform.

These meanings must not be overloaded or redefined.

---

## Recommendation

Means:

A deterministic recommendation produced by the Recommendation Engine.

Does NOT mean:

- An AI suggestion
- An opinion
- A language model response

---

## Confidence

Means:

A deterministic measurement produced by the Confidence Engine representing support from Behavioral Evidence.

Does NOT mean:

- LLM confidence
- Probability of model correctness
- AI certainty

---

## Memory

Means:

Behavioral Memory represented as a Runtime Object.

Does NOT mean:

- LLM conversational memory
- Chat history
- Prompt context

---

## Journey

Means:

A deterministic business journey representing progress toward a business objective.

Does NOT mean:

- A chat conversation
- A browser session
- A user login session

---

## Truth

Means:

A deterministic platform conclusion supported by Runtime Objects and Decision Policies.

Truth is established by the Behavioral Intelligence Platform.

AI communicates truth.

AI never establishes truth.

---

## Capability

Means:

A vendor-neutral business function supported by one or more products.

Does NOT mean:

- Software feature
- Marketing feature
- UI functionality

---

## Runtime Object

Means:

An immutable, versioned representation of deterministic platform knowledge.

Does NOT mean:

- Database row
- ORM entity
- Programming object
- API request model

---

## Platform Engine

Means:

A deterministic platform component with one clearly defined responsibility.

Does NOT mean:

- AI model
- Workflow engine
- Generic software service

Every important platform concept has exactly one canonical name.

Synonyms should be avoided.

1. Update the Platform Glossary.
2. Update dependent architecture documents.
3. Deprecate the previous terminology.
4. Maintain consistency across the repository.

# Writing Guidelines

Architecture documentation should:

- Use canonical terminology.
- Avoid ambiguous language.
- Prefer deterministic wording.
- Prefer platform-defined nouns.
- Avoid implementation-specific terminology unless required.

Documentation should describe:

- Responsibilities
- Contracts
- Runtime Objects
- Platform behavior

Documentation should avoid:

- Implementation assumptions
- Technology-specific language
- Temporary naming
- Informal synonyms
