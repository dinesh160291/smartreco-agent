# Confidence Engine

**Version:** 1.0

---

# Purpose

The Confidence Engine (CE) is responsible for determining the deterministic confidence associated with each Behavioral Hypothesis based on accumulated Behavioral Evidence.

Confidence represents the platform's certainty in its current understanding of the user's behavior.

Confidence is deterministic.

Confidence is never generated by AI.

The Confidence Engine never:

- Creates Behavioral Hypotheses.
- Generates recommendations.
- Invokes AI.
- Makes business decisions.

Its sole responsibility is evaluating confidence.

---

# Guiding Principle

Confidence is not the probability that a user will purchase.

Confidence represents the deterministic certainty associated with a Behavioral Hypothesis based on accumulated Behavioral Evidence.

Confidence is earned through evidence.

It is never guessed.

It is never generated by AI.

---

# Responsibilities

The Confidence Engine is responsible for:

- Updating Behavioral Hypothesis confidence.
- Evaluating supporting Behavioral Evidence.
- Evaluating contradicting Behavioral Evidence.
- Rewarding behavioral consistency.
- Applying diminishing returns.
- Producing deterministic Confidence Explanations.
- Updating Confidence Metadata.

The Confidence Engine never:

- Creates Behavioral Hypotheses.
- Creates Behavioral Evidence.
- Modifies Journey Memory.
- Generates recommendations.
- Invokes AI.

# Inputs

The Confidence Engine consumes:

- Current Behavioral Hypothesis

Business thresholds governing confidence are defined externally by Decision Policies.

- Minimum confidence required for Recommendation Readiness.

The Confidence Engine consumes these policies.

This separation allows business rules to evolve independently of engine implementation.

# Evidence Diversity

Behavioral diversity strengthens confidence.

Example

GitHub

↓

API Documentation

↓

Security Documentation

↓

Architecture Whitepaper

↓

Enterprise Pricing

This collection of diverse behavioral evidence supports confidence more strongly than repeatedly observing the same behavioral signal.

Evidence diversity improves confidence because it demonstrates consistent intent across multiple independent behaviors.

Diversity is paid by the combination rule, not by a separate bonus. Independent readings of one concept — a different kind of behavior, a different pattern, a higher strength — each contribute their own term, and the terms combine by noisy-OR. A second pattern therefore raises confidence by construction. Decision #091 retired POL-CONF-001's flat diversity increment for this reason: under a combination that already rewards independence, an added bonus paid for the same diversity twice.

# Diminishing Returns

Repeated identical Behavioral Evidence contributes progressively less confidence.

Behavioral confidence naturally saturates over time.

Repeated identical actions should never produce unlimited confidence growth.

Example

Viewing the same pricing page twenty times should not increase confidence as much as observing:

- Pricing
- Documentation
- API Reference
- Security
- Integrations

Confidence grows through evidence quality rather than evidence quantity.

## The damped unit is the action

The rule above is written about actions — twenty views of one page — and that is what is counted. It is *not* the Evidence record. A session-window pattern re-reports every qualifying event in its session on each workflow run, so a single finding reaches this engine as a stream of overlapping records; treating each record as a repetition confuses how often the platform looked with how much the shopper did.

Each supporting event is counted once, against the identity it belongs to (pattern, strength, kind of behavior). Two consequences follow, and both are load-bearing:

- A run that observed **no new action** cannot move confidence at all. Not a little, not below the sixth decimal — nothing. Inflation from re-reporting is removed rather than damped.
- Confidence keeps growing while the shopper keeps doing genuinely new things, saturating only at the POL-CONF-004 cap.

Saturation therefore belongs to the cap, and to nothing else. Before Decision #091 the running sum was a convergent series whose limit was fixed by how many kinds of behavior a shopper happened to produce, so a concept could have a ceiling *below* the thresholds it feeds — a subject supported by 46 events converged on 0.4999… against a publication bar of 0.5 and could never be published no matter how long the shopper kept going. A ceiling that depends on browsing texture rather than on evidence is not saturation; it is an artifact.

# Confidence Explanation

Every Behavioral Hypothesis maintains a deterministic Confidence Explanation.

A Confidence Explanation documents why the current confidence exists.

Every Confidence Explanation contains:

- Supporting Behavioral Evidence
- Contradicting Behavioral Evidence
- Evidence Diversity
- Evidence Recency
- Evidence Strength
- Last Updated Timestamp
- Deterministic Explanation

Examples include:

- Reinforced by diverse enterprise research across multiple sessions.
- Confidence reduced due to contradictory behavioral evidence.
- Strong confidence maintained through repeated independent observations.
- Confidence limited because evidence diversity remains low.

Confidence Explanations are deterministic runtime objects.

They are never generated by AI.

The AI Buying Advisor may reference Confidence Explanations when communicating recommendations, but it never modifies them.
